## 🌟 Overview

**Strauss CarWise** is a Full Stack AI-powered vehicle advisory application designed to help employees make informed decisions about company car options.

Instead of navigating complex eligibility rules, vehicle catalogs, and salary calculations manually, employees can interact with a conversational assistant in Hebrew.

The system combines **natural-language understanding with deterministic financial calculations**, ensuring that AI helps interpret requests while verified application logic handles business rules and numerical results.

The project demonstrates the integration of modern Full Stack development, relational databases, authentication, security, and AI-driven workflows.

## 🏗️ System Architecture

The application separates AI interpretation, business logic, and data access.

```text
                  EMPLOYEE
                     |
                     v
             Next.js / React UI
                     |
                     v
             Application API
                     |
          +----------+----------+
          |                     |
          v                     v
    AI Interpretation     Business Logic
    Natural Language      Eligibility Rules
    Structured Actions    Financial Calculator
          |                     |
          +----------+----------+
                     |
                     v
             Validated Operations
                     |
                     v
             Supabase / PostgreSQL
                     |
             Auth + RLS + Data
```

### Key Architectural Principle

**AI interprets intent. Application code controls execution.**

The LLM does not independently determine salary calculations or bypass authorization rules.

Requests are interpreted, validated, and processed through controlled application logic.

This design improves reliability, testability, and security.

## 🧮 Financial Calculation Engine

One of the central engineering components is a deterministic calculation engine.

The system combines:

- Employee salary data
- Occupation-based eligibility
- Vehicle catalog data
- Vehicle benefit-in-kind values
- Tax and social contribution rules
- Employee participation amounts
- Waiver and special-track rules

### Vehicle Tax Record Lookup

Vehicle tax values are matched using a structured composite key:

```text
Tax Year
+ Registration Year
+ Vehicle Type Code
+ Manufacturer Code
+ Model Code
```

Vehicle identifiers are preserved as strings to retain leading zeros.

### Calculation Principles

- Monthly tax calculations based on the challenge specification
- No intermediate rounding during calculation
- Rounding only when displaying results
- Deterministic results independent of LLM output
- Explicit separation between estimated calculations and real payroll data

The challenge's simplified tax model uses specified 2025 tax tables and is not intended to replace an official payroll calculation.

## 🚀 Getting Started

### Prerequisites

- Node.js 20.9 or later
- npm
- A configured Supabase project

### 1. Clone the repository

```bash
git clone https://github.com/RacheliWasserman/strauss-carwise.git
cd strauss-carwise
```

### 2. Install dependencies

```bash
npm install
```

### 3. Configure environment variables

Copy the example environment file:

```bash
cp .env.example .env.local
```

Configure the required Supabase credentials and any AI provider credentials required by the current implementation.

Never commit API keys or Supabase secret keys to Git.

### 4. Prepare the database

Review the SQL migrations under:

```text
supabase/migrations/
```

Apply only migrations that match the current database schema and have been reviewed.

See the documentation under `docs/` for migration and authentication guidance.

### 5. Run the application

```bash
npm run dev
```

Open:

http://localhost:3000

### 6. Run tests

```bash
npm test
```

### 7. Verify the production build

```bash
npm run build
npm start
```

## 🔒 Security Considerations

The application handles potentially sensitive employee and financial information.

Its security design includes:

- Authentication and role separation
- Row-Level Security policies
- Server-side ownership and authorization checks
- Controlled AI operation execution
- Validation of structured AI responses
- Protection of secret credentials

**Production note:** Before using real employee payroll information, the system requires a complete review of employee identity mapping, data access permissions, privacy and retention policies, request limits, and security controls.

## ⚠️ Project Scope & Disclaimer

This project was developed using challenge-provided datasets and business rules.

Financial outputs are **estimates for demonstration and decision-support purposes**.

They are not official Strauss payroll calculations, and the application should not be treated as a production payroll system.

Some project components may continue to evolve as development progresses.
